## Architecture and ownership

Use the existing Python custom-node extension, Comfy native execution/model management, the current JavaScript Desktop UI, and the revisioned asset store. `store.py` owns revisions, dependencies and immutable job inputs. `recipes.py` owns actual graph connections. `nodes.py` owns saved disk boundaries. `profiles.py` and the model lock own recipe compatibility and pinned files. `description_helper.py` owns model-aware language. `routes.py` owns stage actions; `web/creator.js` owns the visible sequence. Add focused modules only where an independent lifecycle or camera contract needs a single owner.

Resource release is an implementation requirement, not an operator reminder. Finish or cancel each heavy job, preserve its output, request Comfy's native model unload **and execution-cache reset**, wait for queue drain and observable release, record before/peak/after process RAM, system available RAM, VRAM, and live tensor memory. Run the same cleanup on failure. Release the description-helper subprocess in `finally`. Never call an allocator-cache clear proof that live models or tensors were released. Do not begin a dependent heavy stage while cleanup is pending or the configured reserves are unmet. Preserve unrelated jobs and applications; release only when Comfy is idle. Measure and bound feature-map/intermediate lifetimes rather than lowering detail without consent.

Brian's additional sequencing requirement: text-encoder weights must be offloadable after producing conditioning and before image sampling; image-generation weights and temporary intermediates must be released before reconstruction. CPU offload still consumes system RAM and is not equivalent to full release. Verify the native graph's actual load/offload order and retain only conditioning needed by the current sampler, then clear that conditioning at its completed stage boundary.
